# Set1080p
##網站連結:https://ryanchiu623-wq.github.io/set1080p/
一鍵把 Windows 顯示設定調整到簡報用組態的小工具。靜默執行，成功時完全無感；失敗才會跳視窗並自動留下記錄檔。

專為「接投影機／外接螢幕前要先把顯示設定橋好」的情境設計，適合放進開機自動執行。

---

## 功能

執行後會依序做三件事：

| 順序 | 項目 | 目標值 | 實作方式 | 納入成敗判斷 |
|---|---|---|---|---|
| 1 | 投影模式 | 同步（Duplicate / Clone） | `DisplaySwitch.exe /clone` | ✗ 僅記錄 |
| 2 | 螢幕解析度 | 1920 × 1080 | `ChangeDisplaySettings` | ✓ |
| 3 | DPI 縮放 | 125% | `DisplayConfigSetDeviceInfo`（未公開 API） | ✓ |

**為什麼投影模式不列入成敗判斷？**
`DisplaySwitch.exe` 不會回傳有意義的結束代碼，切換成功或失敗都是 0。既然無法可靠偵測，就不拿它決定「失敗」與否——否則錯誤訊息會失真。它的執行狀態仍會寫進 log。

## 自檢與重試機制

```
切換投影模式（前置，不判斷成敗）
        ↓
┌─── 第 1 次嘗試 ────────────────┐
│  套用解析度 1920×1080          │
│  套用 DPI 125%                 │
└────────────────────────────────┘
        ↓
    兩項都成功？ ── 是 ──→ 靜默結束（不寫 log、不跳窗）
        │
        否
        ↓
    等待 1.5 秒
        ↓
┌─── 第 2 次嘗試 ────────────────┐
│  只重試「上次失敗」的項目      │
│  已成功的項目略過，避免重複    │
│  套用造成畫面閃爍              │
└────────────────────────────────┘
        ↓
    仍有失敗？ ── 是 ──→ 寫 log ＋ 跳出錯誤視窗
        │
        否 ──→ 靜默結束
```

重點：**重試只針對失敗項目**。如果解析度第一次就成功、只有 DPI 失敗，第二次不會再動解析度。

## 記錄檔（Log）

### 產生時機

**只在重試後仍失敗時才寫入。** 成功執行不留任何檔案。

這是刻意的設計——這支程式是開機靜默執行的，每次都寫檔會讓 D: 很快堆滿無意義的小檔。

> 若想改成「每次執行都留記錄」，把 `Main()` 結尾 `if (!allOk)` 區塊內的 `WriteLog(log.ToString())` 移到 `if` 外面即可。

### 儲存位置

| 優先序 | 路徑 | 說明 |
|---|---|---|
| 1 | `D:\Set1080p_Log\` | 主要位置，資料夾不存在會自動建立 |
| 2 | `%TEMP%\Set1080p_Log\` | 備援。D: 不存在或無寫入權限時自動改用 |

兩者都失敗時程式不會崩潰，錯誤視窗會改為提示「記錄檔寫入失敗」。

### 檔名格式

```
Set1080p_YYYYMMDD_HHmmss.log
例：Set1080p_20260731_143052.log
```

帶時間戳記，多次失敗不會互相覆蓋。

### 編碼

UTF-8 **含 BOM**（`EF BB BF`）。加 BOM 是為了讓 Windows 記事本直接開啟時中文不變亂碼。

### 內容範例

```
========================================
 Set1080p 執行記錄
 時間：2026-07-31 14:30:52
 電腦：DESKTOP-ABC123 / 使用者：Ryan
========================================

[前置] 投影模式 -> 同步 (Duplicate)
       已送出 DisplaySwitch /clone 指令

[第 1 次嘗試]
  解析度 1920 x 1080 ... OK
  DPI 縮放 125%      ... 失敗

>> 有項目未成功，1.5 秒後自動重試一次...

[第 2 次嘗試]
  解析度 1920 x 1080 ... 已成功（略過）
  DPI 縮放 125%      ... 失敗

最終結果：重試後仍有項目失敗
```


## 編譯

原始碼是單檔無外部相依，只用到 `mscorlib` 和 `System`。

**Windows（.NET Framework SDK / Visual Studio Build Tools）**

```bat
csc /target:winexe /platform:anycpu /optimize+ Set1080p.cs
```

**Linux / macOS（Mono，可交叉編譯出 Windows 執行檔）**

```bash
mcs -target:winexe -platform:anycpu -optimize+ -out:Set1080p.exe Set1080p.cs
```

`-target:winexe` 是關鍵——用 `exe` 會多跳一個黑色 console 視窗。

編譯結果應為：`PE32 executable (GUI)`、runtime `v4.0.30319`。

### 執行需求

- Windows 10 1703（Creators Update）以上
  DPI 相關的 `DISPLAYCONFIG_DEVICE_INFO_TYPE` 私有值在此版本後才穩定
- .NET Framework 4.x（Windows 10/11 內建）
- 一般使用者權限即可，**不需要系統管理員**

## 部署：開機自動執行

### 方法 A — 啟動資料夾（最簡單）

1. `Win + R` → 輸入 `shell:startup` → Enter
2. 把 `Set1080p.exe` 的**捷徑**放進去

缺點：登入後才執行，時機較晚，偶爾會早於顯示驅動就緒。

### 方法 B — 工作排程器（較穩定，建議）

1. 開啟「工作排程器」→ 建立工作
2. **一般**：勾選「不論使用者登入與否均執行」視需求調整
3. **觸發程序**：登入時 → 延遲工作 `30 秒`
4. **動作**：啟動程式 → 指向 `Set1080p.exe`
5. **條件**：取消勾選「只有在電腦使用 AC 電源時才啟動」（筆電必做）

延遲 30 秒是重點——顯示卡驅動與螢幕拓撲需要時間就緒，太早跑必失敗。

## 疑難排解

| 症狀 | 可能原因 | 處理方式 |
|---|---|---|
| 解析度兩次都失敗 | 螢幕／投影機不支援 1920×1080 | 用「顯示設定」確認可用解析度清單，改目標值 |
| 解析度兩次都失敗（手動設可以） | 時序問題：投影拓撲尚未穩定 | 拉長 `SetDuplicateProjection()` 內的 `Thread.Sleep(1500)` 到 3000 |
| DPI 設定回報成功但畫面沒變 | Windows DPI 變更部分情況需重新登入 | 登出再登入後確認 |
| DPI 兩次都失敗 | 該 Windows 版本不支援此私有 API | 見下方「技術備註」 |
| 投影模式沒切換 | 受管理電腦封鎖 `DisplaySwitch.exe` | 檢查群組原則；非程式問題 |
| 沒有產生 log | **正常** — 成功時不寫檔 | 確認顯示設定是否已正確套用 |
| exe 無法啟動、跳 .NET 錯誤 | 執行環境缺 .NET Framework | 安裝 .NET Framework 4.8 |

## 自訂參數

要改目標值，直接改 `Main()` 裡這兩行：

```csharp
resOk = SetResolution(1920, 1080);   // ← 改解析度
dpiOk = SetDpiForAllSources(125);    // ← 改 DPI 百分比
```

DPI 只接受這份清單裡的值（Windows 本身的限制）：

```
100, 125, 150, 175, 200, 225, 250, 300, 350, 400, 450, 500
```

改 log 路徑則改 `WriteLog()` 裡的：

```csharp
string dir = @"D:\Set1080p_Log";
```

## 技術備註

### DPI 設定用的是未公開 API

`DISPLAYCONFIG_DEVICE_INFO_TYPE` 的 `-3`（GET）與 `-4`（SET）是微軟**未公開文件**的私有值。Windows 的「顯示設定」介面內部就是走這條路，但它不在官方 API 契約內，理論上有可能在未來版本失效。

### 相對索引的運作方式

DPI 不是直接設百分比，而是設「相對於系統建議值的索引位移」：

- `minScaleRel` 的絕對值 = 建議值在縮放清單中的位置
- `scaleRel = 目標索引 − 建議值索引`

例：清單中 125% 索引為 1，系統建議值為 100%（索引 0），則 `scaleRel = 1`。
程式會自動用 `minScaleRel` / `maxScaleRel` 做上下限夾擠，避免設出無效值。

### 多螢幕行為

`SetDpiForAllSources()` 會走訪所有作用中的 display path 並逐一套用，只要**任一個**成功就視為成功（`anyOk`）。切到同步模式後通常只剩一個 source，這在實務上不成問題。
